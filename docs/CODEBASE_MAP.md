# Codebase Map — Grid's Eye View (gridseyeview.com)

Last verified: 2026-07-06. Fork of `koala73/worldmonitor` v2.6.7, rebranded, running the `energy` variant.

## Frontend

- **Stack**: TypeScript SPA, no framework (vanilla TS component classes, some Preact), Vite 6, deck.gl 9 + MapLibre for the map, globe.gl for 3D globe, i18next, PWA via vite-plugin-pwa.
- **Entry points**: `index.html` → `src/main.ts` (Sentry, analytics, fetch patches, theme) → `src/App.ts` (`App.init()` runs 8 phases: storage/i18n → panels → map → services).
- **Variant system**: `src/config/variant.ts` reads `VITE_VARIANT`. Energy config: `src/config/variants/energy.ts` (panels: map, energy-stats, energy news, AI insights, energy-complex, monitors; layers: usPlants, usTransmission, oilGasPipelines, oilGasFields, weather, waterways, natural, fires).
- **Energy-specific code**: `src/services/energy-events.ts` (threshold-crossing event feed polling `/api/eia-*`), `src/services/eia-live.ts`, `src/components/EnergyStatsPanel.ts`, `EnergyComplexPanel.ts`, `src/components/gev/GevDrawer.ts`.
- **Protected (per CLAUDE.md, do not modify)**: `DeckGLMap.ts`, `Map.ts`, `GlobeMap.ts`, `data-loader.ts`, everything in `src/services/`, `api/`, `server/`.
- **GEM data**: `public/data/gem-pipelines.json` / `gem-fields.json`, loaded at runtime by `src/config/gem-data.ts`; regenerated by `scripts/gen-gem-json.cjs`.

## Backend (existing — all TypeScript/JS, serverless)

- **`api/`**: ~80 Vercel edge functions. Energy-relevant: `eia-demand.js`, `eia-generation.js`, `eia-price.js`, `eia-gas.js` (thin proxies over EIA v2 with 15-min edge cache), `energy-news.js`, `chat-analyst.ts` (Pro-gated SSE chat using Groq/OpenRouter via `server/_shared/llm`).
- **`server/`**: shared gateway (`gateway.ts` — CORS, API-key validation, rate limiting, entitlement checks, cache tiers) + per-domain sebuf-generated route handlers under `server/worldmonitor/<domain>/v1/`.
- **`convex/`**: Convex Cloud deployment — payments (**Dodo Payments**, not Stripe), `entitlements.ts`, `alertRules.ts`, `notificationChannels.ts` (telegram/slack/email/discord), Resend webhook handling, user preferences sync, registrations. One cron (pairing-token cleanup).
- **`middleware.ts`**: Vercel middleware (bot filtering, social OG).

## Existing data ingestion

There is **no persistent time-series store**. Two patterns today:

1. **Fetch-on-request** edge proxies with `Cache-Control` edge caching (15 min for EIA endpoints).
2. **Railway seed loops**: `scripts/ais-relay.cjs` (WebSocket relay) + `scripts/seed-*.mjs` crons writing JSON blobs to **Upstash Redis with TTLs**. `scripts/seed-electricity-prices.mjs` seeds EIA RTO daily prices (CISO/MISO/PJM/NYIS/ERCO/SWPP) + ENTSO-E day-ahead for 10 EU zones, TTL 3 days.

History is therefore capped at Redis TTL (days). Nothing stores hourly settlement prices, nothing tracks revisions, no heartbeats.

## Database schema

- **Convex** (`convex/schema.ts`): userPreferences, notificationChannels, alertRules (with quiet hours + digest mode), telegramPairingTokens, registrations, contactMessages, payment/subscription tables via `@dodopayments/convex`.
- **Upstash Redis**: cache keys, seed-meta freshness, rate limiting. No relational DB anywhere.

## Deployment

- **Vercel**: SPA + edge functions at gridseyeview.vercel.app. `vercel.json`: crons empty, rewrites for /docs (Mintlify), /pro, /mcp, /oauth; strict CSP.
- **Railway** (upstream worldmonitor): AIS relay + seed crons + notification relay (`scripts/notification-relay.cjs`, Telegram bot + Resend email). Unclear whether this fork has its own Railway deployment.
- **Convex Cloud**: registrations/payments (upstream; fork's own deployment status unclear).
- Local env (`.env`): only `EIA_API_KEY` + `VITE_EIA_API_KEY` set.
